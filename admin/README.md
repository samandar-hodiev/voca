# Voca Admin Dashboard

The owner/admin web application. Next.js, TypeScript, Tailwind CSS.

## Status

**Structural scaffold only. Not initialized, not running, no UI.**

Every `.ts` file here is a placeholder carrying a comment about what belongs in it. There
is deliberately **no `package.json`, `tsconfig.json`, `next.config.js` or Tailwind config**,
because those are generated by tooling rather than written by hand:

```
cd admin
npx create-next-app@latest . --typescript --tailwind --app --eslint
```

Run that when admin implementation actually begins. It will generate the configuration
around the `src/` tree that already exists. This mirrors how `mobile/` works, where
`android/` and `ios/` are generated by `flutter create` rather than committed by hand.

Full architecture: `docs/architecture/ARCHITECTURE.md`, section 38.

## Structure

```
admin/
├── src/
│   ├── app/           Next.js App Router. Routes map onto features.
│   ├── components/
│   │   ├── ui/        Design-system primitives (button, table, card, dialog)
│   │   └── layout/    Shell: sidebar, header, page frame
│   ├── features/      One folder per admin capability
│   │   ├── auth/           admin sign-in and session
│   │   ├── dashboard/      overview metrics
│   │   ├── users/          learner accounts, progress, entitlement
│   │   ├── content/        words, categories, CEFR, AI moderation queue
│   │   ├── pronunciation/  score and phoneme analytics
│   │   ├── analytics/      retention, funnels, conversion
│   │   ├── subscriptions/  billing state and churn
│   │   ├── notifications/  campaigns and delivery
│   │   └── system/         API health, provider usage, errors, cost
│   ├── hooks/         cross-feature React hooks
│   ├── lib/           pure helpers: formatting, permission display logic
│   ├── services/      apiClient, authService
│   ├── types/         shared API envelope types
│   └── config/        typed environment access
└── public/
```

Each feature folder holds `api.ts`, `types.ts`, `index.ts`, plus `components/` and
`hooks/`. Other features import a feature only through its `index.ts`, so a feature stays
removable.

## Non-negotiable boundaries

These are the rules that keep the three applications from decaying into one tangle.

- **No database access.** The admin has no PostgreSQL driver and no connection string. It
  reaches data only through `/api/v1/admin/*`.
- **No business logic.** Scoring, entitlement, quota, moderation rules and recommendation
  logic live in the Go backend and are never reimplemented here.
- **No secrets.** Everything prefixed `NEXT_PUBLIC_` is compiled into the browser bundle
  and readable by anyone. Only the API base URL and environment name belong there. No
  Azure key, no AI provider key, no RevenueCat secret.
- **Route guards are cosmetic.** Hiding a page does not protect it. Every privileged
  request is authorized again by the backend.
- **No shared UI code with Flutter.** Mobile and admin share design *tokens and
  principles*, never components. See `docs/architecture/ARCHITECTURE.md` section 44.
